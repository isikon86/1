# TEOT Survival HUD v0.2.1 — исправленный запуск и прозрачный фон

## Исправлено
- В `fxmanifest.lua` есть точная обязательная строка `rdr3_warning` для RedM.
- Убрана жёсткая зависимость `dependency 'vorp_metabolism'`, из-за которой ресурс мог отказываться запускаться, если название/состояние зависимости не совпадало. HUD по-прежнему читает VORP Metabolism, если он запущен.
- В HTML/CSS явно задан полностью прозрачный фон `html`, `body` и `#hud`. В ресурсе нет полноэкранной чёрной панели; рисуются только маленькие индикаторы.
- Сон и психика по-прежнему не входят в базовый HUD — позже будут отдельными ресурсами.

## Правильная установка (важно не сделать вложенную папку)
1. Останови старый ресурс:
   `stop teot_survivalhud`
2. Сделай резервную копию старой папки.
3. Удали/переименуй только старую папку `teot_survivalhud`, если в ней находятся предыдущие файлы. Не трогай VORP или другие ресурсы.
4. Распакуй этот архив в `resources/[local]/` (или другую свою группу ресурсов). В итоге путь должен быть ровно:
   `resources/[local]/teot_survivalhud/fxmanifest.lua`
   НЕ должно получиться:
   `resources/[local]/teot_survivalhud/teot_survivalhud/fxmanifest.lua`
5. Открой `fxmanifest.lua` именно в этой папке и убедись, что третья строка содержит:
   `rdr3_warning 'I acknowledge that this is a prerelease build of RedM, and I am aware my resources *will* become incompatible once RedM ships.'`
6. Убедись, что `vorp_metabolism` запускается раньше HUD. В `server.cfg` достаточно одной строки для нового ресурса:
   `ensure teot_survivalhud`
7. Выполни `refresh`, затем `ensure teot_survivalhud`.

## Проверка
- Предупреждение об отсутствующем `rdr3_warning` должно исчезнуть, если сервер читает этот `fxmanifest.lua`.
- Стандартная мини-карта скрывается.
- На экране остаётся только маленький HUD по центру снизу; фон прозрачный.
- Голод/жажда должны продолжать работать при запущенном `vorp_metabolism`.

Если сервер всё ещё пишет `Couldn't start resource`, это уже отдельная ошибка запуска: пришли строки консоли сразу ПОСЛЕ этой фразы целиком. Само предупреждение о `rdr3_warning` обычно не объясняет причину отказа запуска.

### Установка

### Статус тестирования
Архив и обязательные файлы проверяются статически. Проверка на живом RedM-сервере не выполнялась; после установки нужно подтвердить, что твоя версия RedM отдаёт температуру через `GetTemperatureAtCoords`.


## v0.2.30 — один адаптивный индикатор температуры

- Удалены два отдельных медальона «Холод» и «Жара»; вместо них один медальон в том же размере и позиции.
- В холоде внутри кольца отображается снежинка с голубым мерцанием и небольшими искрами, расходящимися по сторонам.
- При умеренной температуре в одном значке видны левая половина снежинки и правая половина пламени; свечение мягкое, золотистое.
- В жаре отображается пламя с тёплым янтарно-красным мерцанием и искрами.
- При экстремальном холоде снежинка часто вспыхивает ледяным голубым; при экстремальной жаре пламя часто мигает тёплым красным.
- Режим выбирается по температуре окружающего мира: ниже `Config.ColdStartC` — холод, выше `Config.HeatStartC` — жара, между порогами — умеренно.
- Сохранены размер и расположение HUD, существующие анимации здоровья/стамины/еды/воды/микрофона, прозрачный фон и все текущие функции.
- Пороги по-прежнему настраиваются в `config.lua`. Последствия для здоровья/стамины не добавлялись.

### Установка
1. Сделай резервную копию папки `teot_survivalhud`.
2. Замени её целиком папкой `teot_survivalhud` из этого архива.
3. Выполни `restart teot_survivalhud`.
4. Проверь один значок в холодном регионе, в умеренной зоне и в жаркой пустыне.

Статус: архив проверен на целостность и JavaScript — синтаксис проверен. Фактическое отображение и native температуры требуют проверки в живой RedM-игре.
